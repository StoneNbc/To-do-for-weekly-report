## 1. 文档目的

本文档定义“设置”功能第一版的产品范围、交互规则、配置语义和验收标准，作为后续界面设计、技术设计、开发和测试的依据。

若本文档与主 PRD 的核心业务规则冲突，以主 PRD 为准；新增设置不得改变以下既有原则：

- `today.txt` 与 `weeks/*.txt` 仍是任务数据的唯一事实来源。
- 设置只保存到本地，不引入账号、云同步、遥测或网络请求。
- Renderer 不直接访问文件系统，所有桌面能力通过受控接口调用主进程。
- 每日归档时间继续固定为 `00:00`，第一版设置界面不允许修改。
- 未知配置字段继续保留，不因本功能写回配置而被静默删除。

## 2. 背景与问题

当前悬浮窗菜单中的“设置”只是禁用占位项，用户只能通过菜单切换保持置顶，无法在界面中统一查看和调整应用偏好。

同时存在以下体验缺口：

- 便利贴背景固定为淡黄色，不能适应不同桌面壁纸或个人偏好。
- 便利贴不透明度固定，可能遮挡桌面内容。
- 置顶状态虽然能够持久化，但界面缺少统一、可信的当前配置来源。
- 已完成区域的展开状态已有配置基础，但尚未形成完整的持久化体验。
- 数据目录已有打开入口，日志目录缺少面向用户的诊断入口。

设置功能第一版需要解决以上问题，同时保持产品轻量、本地优先和低学习成本。

## 3. 产品目标

### 3.1 核心目标

1. 用户能够从应用主要菜单进入独立设置窗口。
2. 用户能够修改便利贴颜色和整体不透明度，并立即看到效果。
3. 用户的设置修改能够自动保存，下次启动时保持上次成功保存的选择。
4. 用户能够统一管理保持置顶和已完成区域展开状态。
5. 用户能够快速定位数据与日志目录，便于备份和排查问题。

### 3.2 体验目标

- 无需理解配置文件即可完成常用设置。
- 修改后立即生效，不要求额外点击“保存”。
- 设置窗口始终清晰可读，不受便利贴颜色和不透明度影响。
- 设置失败时给出可理解的反馈，不静默丢失或伪装成保存成功。

### 3.3 非目标

第一版不包含：

- 自定义周报模板。
- ReportAgent 或 AI 服务选择。
- 修改每日归档时间。
- 修改或迁移数据存储目录。
- 云同步、账号或跨设备同步。
- 字体、字号、圆角、阴影等完整主题编辑器。
- 为周记窗口设置颜色或透明度。
- 导入、导出或同步整套设置。

## 4. 用户场景

### 4.1 调整便利贴外观

用户希望便利贴与桌面环境协调，在设置中选择蓝色并将不透明度调为 80%。便利贴应在调整过程中实时变化，并在下次启动时继续使用蓝色和 80% 不透明度。

### 4.2 减少桌面遮挡

用户希望在查看任务的同时看到便利贴下方内容，将不透明度降低到允许范围。文字、按钮和背景作为整个便利贴窗口一起变淡。

### 4.3 恢复默认外观

用户尝试自定义颜色后希望回到产品默认视觉，可通过“恢复默认外观”一次恢复默认米黄色和 100% 不透明度。

### 4.4 排查本地数据问题

用户发现记录展示异常时，可从设置窗口直接打开数据文件夹或日志文件夹，无需手工查找系统目录。

## 5. 信息架构

设置窗口第一版分为三个区域：

1. **外观**
   - 便利贴颜色
   - 便利贴不透明度
   - 恢复默认外观
2. **通用**
   - 保持置顶
   - 已完成区域展开状态
3. **数据与诊断**
   - 数据目录路径
   - 打开数据文件夹
   - 打开日志文件夹
   - 复制数据目录路径

设置窗口底部可展示简短说明：“设置仅保存在本机，不会上传。”

## 6. 功能需求

### 6.1 设置入口与窗口

#### SET-ENTRY-01 设置入口

以下位置应提供可用的“设置”入口：

- 悬浮便利贴右上角“…”菜单。
- 悬浮便利贴空白区域的右键菜单。
- 系统托盘右键菜单。

#### SET-ENTRY-02 独立窗口

- 设置以独立的正常窗口打开，不占用悬浮便利贴内容区。
- 窗口标题为“设置”。
- 窗口使用系统边框，可移动、最小化和关闭。
- 关闭设置窗口只关闭该窗口，不退出应用。
- 设置窗口保持完全不透明，不跟随便利贴的不透明度。
- 设置窗口使用稳定的中性背景，不跟随便利贴颜色。

#### SET-ENTRY-03 单例行为

- 同一时间最多存在一个设置窗口。
- 重复点击“设置”时，应显示并聚焦已有窗口。
- 若窗口已最小化，应先恢复再聚焦。

#### SET-ENTRY-04 初始状态

- 打开设置窗口时，应读取主进程当前生效配置。
- 加载期间不得先展示可能错误的默认值再覆盖，避免界面闪烁和误操作。
- 读取失败时显示错误提示和“重试”操作。

### 6.2 便利贴颜色

#### SET-COLOR-01 预设颜色

第一版提供以下预设色：

| 名称 | 色值      | 说明         |
| ---- | --------- | ------------ |
| 米黄 | `#FFF8E7` | 产品默认颜色 |
| 樱粉 | `#FCE7F3` | 柔和粉色     |
| 薄荷 | `#DCFCE7` | 柔和绿色     |
| 天蓝 | `#E0F2FE` | 柔和蓝色     |
| 淡紫 | `#EDE9FE` | 柔和紫色     |
| 雾白 | `#F5F5F4` | 中性浅灰色   |

- 每个预设色同时显示颜色样本和可读名称，不能只依赖颜色传达含义。
- 当前选择具有明确的选中状态，并可通过键盘识别和切换。
- 点击预设色后立即应用到悬浮便利贴并自动保存。

#### SET-COLOR-02 自定义颜色

- 用户可通过系统或浏览器原生取色控件选择自定义颜色。
- 配置使用六位十六进制 RGB 色值，格式为 `#RRGGBB`。
- 输入或选择的颜色必须通过格式校验后才能保存。
- 非法颜色值不得应用，界面应保留上次成功保存的颜色并提示原因。
- 自定义颜色若与预设色相同，可正常显示为对应预设色的选中状态。

#### SET-COLOR-03 文字与控件可读性

- 应根据背景颜色选择适合的前景文字和图标颜色。
- 自定义颜色不应仅因明暗程度被禁止；应用应自动在深色与浅色前景方案中选择对比度更高的一种。
- 若个别次要控件仍无法达到项目采用的可读性标准，应在应用颜色前给出明确警告，不得静默产生不可操作界面。
- 菜单、输入框、错误提示和焦点状态在所有允许颜色上必须保持可辨认。
- 不透明度降低后，应用仍应保留清晰的键盘焦点样式。

#### SET-COLOR-04 应用范围

- 颜色只应用于悬浮便利贴窗口。
- 周记窗口和设置窗口不跟随便利贴颜色。
- 颜色变化不得修改任务文本、周文件或导出周报内容。

### 6.3 便利贴不透明度

#### SET-OPACITY-01 控件与范围

- 使用滑块调整不透明度。
- 允许范围为 60%–100%。
- 默认值为 100%。
- 调整步进为 5%。
- 滑块旁显示当前百分比数值。
- 滑块支持鼠标、触控板和键盘操作。

#### SET-OPACITY-02 透明语义

- 不透明度作用于整个悬浮便利贴窗口，包括背景、文字、图标、菜单和输入控件。
- 设置窗口和周记窗口不受影响。
- 不透明度不得低于 60%，包括配置文件被手工写入非法值的情况。

#### SET-OPACITY-03 实时预览

- 用户拖动滑块时，悬浮便利贴实时显示目标不透明度。
- 为避免高频写盘，拖动过程可以在内存中连续预览，并对持久化写入做短时间防抖。
- 用户结束拖动后，应保存最终值。
- 如果保存失败，应恢复到上次成功保存的值并显示错误提示。

#### SET-OPACITY-04 下次启动保持

- 用户成功保存的不透明度在应用完全退出后仍保留。
- 下次启动时，便利贴直接使用上次成功保存的值。
- 该行为不得表述为“重启后恢复默认值”。

### 6.4 恢复默认外观

#### SET-APPEARANCE-RESET-01 默认值

点击“恢复默认外观”后：

- 便利贴颜色恢复为 `#FFF8E7`。
- 便利贴不透明度恢复为 100%。
- 修改立即应用并自动保存。

#### SET-APPEARANCE-RESET-02 操作边界

- 该操作只重置颜色和不透明度。
- 不修改保持置顶、窗口位置、窗口尺寸、已完成区域状态或业务数据。
- 第一版无需二次确认，因为影响范围小且用户可立即重新调整。

### 6.5 通用设置

#### SET-GENERAL-01 保持置顶

- 使用开关展示和修改便利贴的保持置顶状态。
- 初始值必须来自当前生效配置，不得在 Renderer 中固定为开启。
- 修改后立即应用于悬浮便利贴并自动保存。
- 设置窗口、悬浮窗菜单和托盘菜单应展示一致状态。
- 从任一入口修改后，其他已打开界面应同步更新。

#### SET-GENERAL-02 已完成区域状态

- 使用开关展示“已完成”区域当前保存的展开状态。
- 开启表示便利贴今日视图中的已完成区域展开；关闭表示折叠。
- 从设置窗口修改后，已打开的便利贴应立即同步。
- 用户在便利贴中手动展开或折叠时，也应更新同一持久化状态。
- 下次启动时保持用户上次成功保存的展开或折叠选择。

### 6.6 数据与诊断

#### SET-DIAG-01 数据目录

- 设置窗口展示当前实际使用的数据目录路径。
- 提供“打开数据文件夹”按钮。
- 提供“复制路径”按钮，并在成功后显示轻量反馈。
- 路径只读，用户不能在此直接修改数据目录。

#### SET-DIAG-02 日志目录

- 提供“打开日志文件夹”按钮。
- 打开的目录为应用内部已知日志目录，Renderer 不得提交任意路径。
- 日志目录不存在时，主进程应创建目录或返回可理解的错误。

#### SET-DIAG-03 错误反馈

- 打开目录失败时，Renderer 显示可理解的错误信息。
- 具体系统错误、路径细节和堆栈写入本地日志，不直接暴露底层异常对象。
- 某个诊断操作失败不应影响其他设置项继续使用。

### 6.7 自动保存与状态同步

#### SET-SAVE-01 修改即保存

- 设置窗口不提供全局“保存”按钮。
- 单个设置修改后立即应用，并自动写入本地配置。
- 保存成功后无需弹出阻塞式对话框。
- 对滑块等高频操作允许防抖写入，最终值必须可靠保存。

#### SET-SAVE-02 保存状态

- 保存进行中可显示非阻塞状态，例如“正在保存…”。
- 保存成功后可短暂显示“已保存”，但不应频繁打断用户。
- 保存失败时必须持续显示错误，直到用户重试、再次修改成功或关闭窗口。

#### SET-SAVE-03 多窗口同步

- 设置变更由主进程作为当前配置的权威来源。
- 主进程通知已打开的悬浮窗、设置窗口及需要显示配置状态的其他界面刷新。
- 事件只携带配置失效或安全的配置快照，不携带任意文件内容。
- 多个入口连续修改同一设置时，以主进程最后成功保存的值为准。

## 7. 配置数据需求

### 7.1 配置结构

在现有 `config.json` 基础上新增外观字段：

```json
{
  "schema_version": 1,
  "cleanup_time": "00:00",
  "agent": "template",
  "template_path": null,
  "always_on_top": true,
  "window_bounds": null,
  "completed_expanded": false,
  "note_color": "#FFF8E7",
  "note_opacity": 1
}
```

### 7.2 字段定义

| 字段                 | 类型    | 默认值    | 规则                             |
| -------------------- | ------- | --------- | -------------------------------- |
| `note_color`         | string  | `#FFF8E7` | 六位十六进制 RGB，保存时统一大写 |
| `note_opacity`       | number  | `1`       | 取值 `0.6`–`1`，对应 60%–100%    |
| `always_on_top`      | boolean | `true`    | 沿用现有字段                     |
| `completed_expanded` | boolean | `false`   | 沿用现有字段                     |

### 7.3 兼容与容错

- 旧配置缺少新字段时，使用默认值并在后续配置写入时补齐。
- `note_color` 非法时仅该字段回退默认值，并记录本地警告日志。
- `note_opacity` 不是有限数字或超出允许范围时，仅该字段回退默认值，并记录本地警告日志。
- 其他合法字段不因某个外观字段非法而丢失。
- 当前版本不认识的扩展字段继续原样保留。
- 配置写入继续采用串行队列和安全替换策略。

## 8. 页面与交互设计要求

### 8.1 建议布局

设置窗口采用单列卡片式布局：

```text
┌──────────────────────────────┐
│ 设置                         │
├──────────────────────────────┤
│ 外观                         │
│ 便利贴颜色  ○ ○ ○ ○ ○ ○  自定义 │
│ 不透明度    ─────●─── 80%    │
│              恢复默认外观    │
├──────────────────────────────┤
│ 通用                         │
│ 保持置顶               [开关] │
│ 展开已完成区域         [开关] │
├──────────────────────────────┤
│ 数据与诊断                   │
│ /本机/数据目录…              │
│ [打开数据文件夹] [复制路径]   │
│ [打开日志文件夹]             │
├──────────────────────────────┤
│ 设置仅保存在本机，不会上传。  │
└──────────────────────────────┘
```

### 8.2 响应式与窗口尺寸

- 默认窗口应能在无需横向滚动的情况下完整展示主要控件。
- 内容超出可用高度时允许纵向滚动。
- 窗口缩小后，路径和按钮可换行，但不能相互遮挡。
- 颜色选项在窄宽度下自动换行。

### 8.3 键盘与可访问性

- 所有设置项可通过 Tab 访问。
- 开关使用标准开关或复选框语义。
- 颜色选项具有可读名称、选中状态和焦点状态。
- 不透明度滑块具有名称、当前值、最小值和最大值语义。
- 状态提示使用适合的 `status` 或 `alert` 语义，不只依赖颜色。
- 支持 `prefers-reduced-motion`，设置变化不依赖大幅动画表达结果。

## 9. 异常与边界处理

### 9.1 悬浮便利贴当前未显示

- 用户从托盘打开设置并修改外观时，配置仍应正常保存。
- 下次显示便利贴时直接应用最新设置。

### 9.2 设置窗口打开期间便利贴被关闭或隐藏

- 设置窗口保持可用。
- 外观修改仍写入配置，不因便利贴隐藏而报错。

### 9.3 配置写入失败

- 不得显示虚假的“已保存”。
- 界面恢复到主进程最后成功保存的值。
- 用户可重试，应用其他只读功能仍可使用。

### 9.4 非法手工配置

- 应用启动时按字段回退，不因单个非法字段阻止启动。
- 外观字段非法不得导致窗口不可见、完全透明或无法操作。

### 9.5 多显示器与系统状态

- 修改颜色或不透明度不得改变窗口位置和尺寸。
- 从休眠恢复、切换显示器或改变分辨率后，外观设置保持不变。

### 9.6 平台差异

- 目标平台为 macOS 11+ 和 Windows 10+。
- 若某平台对窗口不透明度的渲染存在差异，应优先保证窗口可操作和内容可辨认，并在测试记录中说明。

## 10. 非功能性需求

- **性能**：颜色或不透明度调整后，应在 100 ms 内给出可见反馈；滑块拖动不得明显卡顿。
- **可靠性**：应用退出前应刷新尚未完成的配置写入。
- **隐私**：设置和诊断功能不得新增任何网络请求或遥测。
- **安全**：Renderer 不得通过诊断入口打开任意用户提交路径。
- **兼容性**：旧版配置可无损升级；未知字段保持不变。
- **可维护性**：配置读取、校验、应用和界面展示使用统一类型定义。
- **可测试性**：配置校验、窗口状态应用和 Renderer 交互均应具备自动化测试入口。

## 11. 验收标准

1. 用户可从悬浮窗菜单、右键菜单和托盘菜单打开设置窗口。
2. 重复打开设置时只存在一个设置窗口，并聚焦已有窗口。
3. 用户可选择任一预设颜色，悬浮便利贴立即更新且配置成功保存。
4. 用户可选择合法自定义颜色，文字和主要控件会自动采用更易辨认的前景方案；非法色值不会覆盖上次成功保存值。
5. 用户可在 60%–100% 范围内以 5% 步进调整整个便利贴窗口的不透明度。
6. 拖动不透明度滑块时预览流畅，结束操作后最终值写入配置。
7. 设置为蓝色和 80% 后完全退出应用，再次启动仍为蓝色和 80%。
8. 点击“恢复默认外观”后，仅颜色和不透明度恢复为米黄色与 100%。
9. 保持置顶状态可从设置窗口修改，并与悬浮窗和托盘菜单保持一致。
10. 已完成区域状态可从设置窗口修改，并与便利贴当前状态保持一致。
11. 用户可打开数据文件夹、复制数据目录路径并打开日志文件夹。
12. 设置窗口与周记窗口不受便利贴颜色和不透明度影响。
13. 单个配置字段非法时，应用仍能启动，其他合法配置不丢失。
14. 配置写入失败时界面显示错误，不伪装成保存成功，并回到上次成功保存的值。
15. 旧版 `config.json` 缺少外观字段时，应用使用默认外观并保持未知扩展字段。
16. 设置功能在正常运行期间不产生网络请求。
17. macOS 11+ 与 Windows 10+ 均完成颜色、不透明度、单例窗口和持久化手工验收。

## 12. 测试建议

### 12.1 配置测试

- 新配置默认值正确。
- 缺少外观字段时补默认值。
- 合法颜色标准化保存。
- 非法颜色、`NaN`、无穷值和越界不透明度按字段回退。
- 更新外观字段时未知字段仍保留。
- 高频不透明度更新后最终落盘值正确。

### 12.2 主进程与 IPC 测试

- 获取设置返回当前生效配置。
- 更新接口拒绝未知或非法输入。
- 设置不透明度后只影响悬浮便利贴窗口。
- 设置窗口单例、恢复和聚焦逻辑正确。
- 打开日志目录不接受 Renderer 任意路径。
- 配置变化能够通知相关窗口。

### 12.3 Renderer 测试

- 加载、保存中、保存成功和保存失败状态。
- 预设颜色、自定义颜色和恢复默认外观。
- 滑块边界、步进、键盘操作和当前值显示。
- 置顶及已完成状态同步。
- 数据与日志入口的成功和失败反馈。
- 全部控件具备可访问名称和焦点状态。

### 12.4 手工平台测试

- macOS 与 Windows 的整个窗口不透明度表现。
- 不同桌面背景下 60%、80% 和 100% 的内容可辨认性。
- 悬浮窗隐藏时修改设置，再次显示后的效果。
- 完全退出并重新启动后的设置保持。
- 多显示器、系统休眠恢复和窗口置顶行为。

## 13. 后续规划

第一版稳定后可单独评审：

- 自定义周报模板与模板预览。
