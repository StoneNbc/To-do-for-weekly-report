## 2. 数据路径与领域契约

复用现有 `data/today.txt` 和 `data/weeks/week-YYYY-Www.txt`，新增 `data/projects.txt`。项目名称只出现在文件内容中，所有路径由 Main 从 `DataPaths.root` 派生固定文件名；不从项目名称构造路径。

新增恢复材料目录 `data/recovery/project-rename/<operation-token>/`，保存改名前文件及恢复清单；格式升级备份放在 `data/recovery/project-format/<original-revision>/`。改名 token 仅定位一次本地维护操作，不是项目或任务 ID。恢复材料不是任务事实来源、周报副本或远程输入，watcher 必须排除整个 recovery 目录。

```typescript
type ProjectStatus = 'active' | 'archived';
type ProjectFilter =
  { kind: 'all' } | { kind: 'unclassified' } | { kind: 'names'; names: string[] };

interface ProjectView {
  name: string;
  status: ProjectStatus;
  color?: string;
}

interface ProjectSnapshot {
  revision: FileRevision;
  projects: ProjectView[];
  warnings: ParseWarning[];
  recovery: { blocked: boolean; message: string; files: string[] };
}

// 扩展现有 TodayTaskView、HistoricalTaskView、WeeklyTask：
// projectName?: string | null;
// TaskLocator 保持不变，禁止新增持久化任务 ID。
```

为兼容既有快照，读取无归属任务时可省略字段，消费端统一用 `projectName ?? null`。新增任务缺省归属为 `null`；编辑请求省略 `projectName` 表示保持，显式 `null` 表示移到未分类，不能混淆。快照中的 projectName 是筛选与展示信息，不作为任务操作定位器。

项目名校验遵循功能设计 §3。目录、任务引用、筛选和改名统一调用同一个比较规则；不得按大小写折叠、模糊匹配或包含关系合并。`names` 至少一个名称；未分类可单独选择，第一版不混合在 names 数组中。

## 3. 文本语法与保真修改

### 3.1 文件声明及项目目录

Today／Week 新格式保留原首行日期／周头，在第二行写入精确声明 `!format:projects-v1`，只允许一个。没有该声明时完全按旧语法读取，末尾类似 `@项目:` 的旧正文不能直接解释为归属。未知版本进入只读诊断状态，禁止用旧解析器写回。

`projects.txt` 首行为 `# projects:v1`，项目块以 `## ` 开始，块尾为下一个项目头或 EOF。头部余下文本是名称，块内 `状态: active`／`状态: archived` 恰好一个，`颜色: #RRGGBB` 至多一个。重复名称、重复字段、缺失状态或非法颜色产生警告；含歧义的目录暂禁项目写入，不能默认覆盖第一项。未知行以 raw 节点保留，排序时与所在项目块一起移动。

未创建目录时，Main 返回稳定的“文件不存在”revision 标记和空目录；首次创建必须再次验证它仍不存在，原子写入后返回实际 revision。外部删除目录不自动推断项目删除，不悄悄重建并吞掉异常。

### 3.2 任务字段顺序与编码

规范任务行：`标题 [ @项目:值][ @添加:YYYY-MM-DD][ @HH:mm]`。最后一项仅完成任务允许；Week 沿用无复选框的完成行。解析按行尾反向进行：合法完成时间 → 合法添加日期 → 一个项目字段 → 标题解码。项目字段独立可选，不要求添加日期存在。

项目值可以是非空 bare token，或一个完整 JSON 字符串。bare token 不得含空白、双引号、反斜杠、控制字符；其他合法名称使用 `JSON.stringify(name)` 编码。引号值必须用字符串词法扫描识别，不能按空格 split；解码后再次执行名称校验。目录中的名称不使用该引号编码。

```text
- [ ] 联系客户 @项目:"客户 A 交付" @添加:2026-09-09
- [ ] 核对资料 @项目:"客户\"甲\"交付" @添加:2026-09-09
- [ ] 整理文档 @项目:"研发\\测试" @添加:2026-09-09
```

新格式标题的转义规则：字面反斜杠编码为 `\\`，字面 `@项目:` 编码为 `\@项目:`；解码只处理 `\\` 和 `\@` 两种序列，其他反斜杠序列保留原样。先解析字段再解码标题，防止字面项目样式被解释为归属。详情行完全沿用原有语法，不应用该转义。

例如文件行 `- [ ] 解释 \@项目:示例 @添加:2026-09-09` 显示标题“解释 @项目:示例”，归属为未分类。旧标题已有反斜杠时按 §8 升级编码，不能丢字符。

同一标题末端有多个未转义项目字段、非法引号或空名称时警告并保留原始任务块，不自动择一或降级为未分类后写回。新格式涉及项目归属的歧义阻止该任务变更；全量改名扫描遇到这类问题必须中止预检并定位文件／行。

### 3.3 AST 与 Repository

新增 `projectParser.ts`、`projectField.ts`、`projectRepository.ts`，扩展现有任务节点的 projectName ；项目字段替换由 `replaceProjectField` 从原始行定位。解析器纯函数，不访问磁盘。

重命名／移动只替换项目字段跨度；无字段时在添加日期／完成时间前插入，移到未分类时删除该字段及其分隔空格。无关标题、详情、注释、空行、换行方式和原文件其余字节保留。目录改名只改对应头部名称，不重排块。正常标题编辑使用编码函数，详情编辑继续按任务块执行。

行号始终为原始文件物理行号，不能用过滤后列表下标。一次批量移动在同一份 AST 上定位全部目标，验证后一次写回并重建行号；完全重复任务逐条保留，不使用正文 Set 去重。

## 4. 服务职责、并发与任务生命周期

新增 `ProjectService`：目录读取／创建／排序／状态变更，精确名称检查，引用扫描和重命名协调。新增 `ProjectRenameService` 专职预检、备份、执行与恢复。目录中缺失但任务引用存在的名称作为派生“未登记项目”展示；只读查询不写目录，用户可显式登记。

所有归属传递路径必须覆盖：Today 添加／编辑／完成／撤销 → Archive 的 `toArchivedTask` → Week 添加／编辑 → History 完成／重新打开 → Weekly 当前周合并 → Report 投影。归档仍先写周文件、成功后再写 today，原有部分失败语义不因项目扩展而被宣称已解决。

新增目标必须是进行中项目或未分类；历史归属纠正也遵循此规则。归档检查当前所有未完成任务；删除及名称冲突检查当前任务与全部有效周文件。无引用删除仍需以提交时的最新数据复核，不能信任预览计数。

现有 TextFileStore 是“每个文件一条写队列”，不能单独保证跨文件改名安全。增加 Main 内统一业务写入协调器：今日、历史转移、零点／唤醒归档、项目变更、watcher 引起的文件初始化均通过它；采用 `BusinessCoordinator` 的同一串行队列与 AsyncLocalStorage 可重入上下文，避免服务递归入队死锁。文件级 revision 校验仍保留。

跨文件改名期间阻止新业务写入，并阻止周报重新采集不一致素材；普通页面保留上一个快照并显示维护状态。外部编辑器不受本进程队列约束：每个目标写入前仍校验 revision，检测到变化进入失败／恢复流程；不能宣称消除了外部编辑的所有竞争窗口。

报告素材采集在协调器中完成必要的跨日补偿和一致读取，取得不可变投影后释放队列，再请求网络，禁止在 LLM 等待期间持有写入队列。应用退出时先停止新工作并排空协调器，再排空 TextFileStore 等现有服务。

## 5. 项目重命名与恢复

### 5.1 预检

1. 校验目录 revision、旧名存在及新名合法；同名请求返回无变更。
2. 在业务队列内先完成必要跨日补偿，再枚举 `today.txt` 和 `weeks/week-YYYY-Www.txt`；按 ISO 周上下文验证周文件，只处理当前 data root。非标准文件不改，标准命名但无法解析的文件阻止预检，避免漏改。
3. 按解析后字段扫描旧名和新名；新名被目录或任务引用占用时拒绝。旧格式无声明的 `@项目:` 正文不是引用。
4. 生成改名前／后的内存文本及 revision，记录目录和数据文件集合；未变化文件不写。扫描时无法读取任一所需文件则失败，不能给出全量完成承诺。
5. 返回短期内存 plan token、文件数、任务数与影响说明；token 绑定确切名称、revision 和文件集合。用户执行时再次验证目录及所有扫描依赖文件的集合／revision，变化则 `FILE_CHANGED` 并重新预览。

### 5.2 备份与写入

备份所有受影响文件的原始字节，写入只含受控相对路径、前后 revision、状态和操作名称的恢复清单。文件与清单需可靠落盘后才允许业务写入；空间不足、权限或备份失败时零业务修改。

业务文件顺序：受影响周文件按文件名排序 → today（若受影响）→ projects 目录最后。每个目标采用现有原子替换路径并校验预期 revision；每步更新持久恢复状态。提交结束再次扫描旧名／冲突和受控文件集合，验证无遗漏后标记 committed，集中广播变更。不要仅依赖可能滞后的步骤状态，恢复时以磁盘前后 revision 判定真实进度。

只允许在当前文件 revision 等于本次写入后 revision 时回滚到备份；等于写入前 revision 表示该文件已经处于原状态。遇到第三种 revision 或文件被外部删除，保留现状并进入人工恢复，不覆盖外部修改。逆序回滚亦采用原子写入与恢复记录，失败不能返回成功。

### 5.3 中断与启动恢复

启动时在开放编辑、自动归档和周报前检查未终结清单；在无第三方变更的情况下按 revision 安全回滚未提交改名。已 committed 的清单不自动回滚；已回滚的清单不重复执行。存在第三种 revision 时显示受影响文件、备份位置和“重新检查／打开恢复目录”入口，暂禁业务写入与生成；允许只读查看并手工处理后再次验证。

备份保留到用户显式清理，不按时间静默删除。操作 token 和清单不得用于任务去重或持久化任务身份。只更新 config 中仍等于旧名的界面偏好；偏好保存失败不回滚已提交任务改名，提示并回退全部视图，启动时校验失效选择。

### 5.4 保证与限制

保证应用协调范围内串行执行、单文件原子替换、可追踪恢复和冲突时不盲目覆盖。无法保证操作系统崩溃／外部编辑下严格多文件事务；不解决既有完成归档的跨文件幂等问题。若改名期间外部创建新周文件或修改扫描范围，提交验证必须失败并进入恢复流程。

监听增加 projects 作用域与维护／恢复状态事件；重命名合并刷新通知，不能把自身多文件写入误认成外部改名。恢复目录、备份及临时文件全部排除。删除项目目录只广播目录缺失，任务引用照常展示，不推测项目映射。

视觉实现（方案 2）：样式集中在 `src/renderer/styles/globals.css`，使用现有 `getNoteTheme` 的前景／表面／边框令牌适配用户背景，容器查询控制底部排列。`DEFAULT_NOTE_COLOR` 为 `#F2F3F5`，设置新增珍珠灰；不迁移旧配置。主窗口尺寸、日期与任务定位契约保持不变。最终全量检查及 GUI／视觉对照按协作流程由用户执行。

## 7. 周记、模板与 LLM 素材

`WeeklyTask` 增加 projectName，保持 content 仅为标题，绝不把详情提升到周聚合对象。当前周追加当天完成项时也必须复制归属；历史周直接使用任务字段，项目目录缺失不阻断素材解释。

生成请求增加 `projectFilter`、`groupBy: 'date' | 'project'`、`includePendingCandidates`（默认 false）。候选从当前未完成任务中应用同一项目过滤，不冒充所选历史周的待办快照；纳入时明确标记为“当前未完成／下周计划候选”。

本地模板保持既有变量含义，新增可选 `{{project_records}}`；按项目模式可通过它输出已筛选分组，现有模板不自动覆写。实现前核实 `reportTemplate.ts` 当前变量表并同步校验器、帮助和双模板预览。远程素材必须包含结构化项目归属，即使用户旧模板未使用新变量，也不能丢失分组信息。可在现有本地记录区附加精简项目分组事实，避免发送同一份完整记录两遍。

将候选输出改为受控对象 `{ content, projectName }[]`（Agent 类型暂兼容旧 string[] 调用），贯穿 `ReportGenerationOptions`、Agent、PromptBuilder 与 mock。构造白名单投影：周范围、所选完成项的 date/content/time/projectName、可选候选的 content/projectName，以及原有模板／提示词。不得 spread 整个任务快照、读入 projects 原文件或传入详情／路径／revision／warning。

生成发送预览与实际请求共享 Main 创建的同一份内存素材快照；变化后重新预览，不能预览一组项目又发送另一组。更新隐私文案版本并由 Main 验证对应授权，现有单个 consent 布尔值不能被当成已实现 origin／版本绑定。项目文本始终作为数据传给模型，不拼进系统权限指令。正常每次生成仍只需一个 LLM 请求；网络策略、取消、超时和草稿另存流程沿用。

导出文件和已生成草稿不参与项目改名。改名使未发送的素材预览失效；已发出的请求可继续基于原快照返回，并显示素材已经更新的提示，用户可重新生成。

## 8. 旧数据升级与回退

1. 普通读取不创建项目、不重写任务。旧 Today／Week 无格式声明时按旧解析器解释，projectName 缺省并按 null 处理。
2. 第一次需要向某文件写入项目字段时，仅升级该文件。取得 revision、先备份原始字节，按旧解析语义提取标题，再对所有合法任务标题应用新转义编码，随后加入第二行格式声明。旧的字面 `@项目:` 和反斜杠必须仍显示原样，不能自动变成项目。
3. 升级与此次文件修改合成一次原子替换；涉及归档目的文件时先完成必要备份再按原归档顺序执行。只读取的历史周无需迁移，重命名仅修改已识别到旧项目引用的文件。
4. 升级无法可靠解析的候选任务行时中止该文件升级并提示定位；原未知行原样保留。旧应用新增于已升级文件的文本无法自动判定意图，因此不支持新旧应用共享同一数据目录写入。
5. 新版读取缺失项目目录仍按任务字段展示未登记分组。人工把目录名称改成新名字后不自动替换任务，需登记旧名再使用统一改名，或手工精确同步全部相关字段。
6. 旧应用不认识新声明与转义，不能承诺防止旧二进制写入或无损降级。回退需关闭应用并恢复升级备份；升级之后新增／修改的数据先另行保留，禁止用旧备份静默覆盖。
