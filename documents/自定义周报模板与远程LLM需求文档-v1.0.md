## 1. 文档目的

本文档定义“自定义周报模板与远程 LLM”第一版的产品范围、用户流程、配置语义、隐私边界、异常处理和验收标准，作为界面设计、开发设计、编码和测试的统一依据。

### 1.1 v1.1 核心修订：本地记录模板与远程完整模板分离

- **本地 TXT 工作记录模板**：只负责把已完成事项整理为确定性的事实记录；选择本地模式时，继续按该模板原样生成，不要求 AI 补写总结。
- **远程完整周报模板**：只在远程模式使用，定义最终周报的完整结构，至少可包含“工作记录、收获与成长、不足与反思、下周计划”。用户可粘贴、编辑或从 `.txt` / `.md` 文件导入。
- **远程写作提示词**：独立于模板保存并允许用户编辑，用于约束写作口吻、事实边界和各章节生成规则。
- **远程生成输入**：本地工作记录、完整周报模板、写作提示词，以及 `today.txt` 中当前未完成待办。未完成待办只作为“下周计划”候选，不代表应用已经提供显式“延后到下周”状态。
- **事实边界**：模型可以依据工作记录归纳收获和不足，但不得虚构项目、成果、数字或未提供的计划。

推荐的远程完整模板：

```text
# 周报模板

=======================
周报 | {{iso_year}}年第{{iso_week}}周
{{week_start}} - {{week_end}}
=======================

【工作记录】
{{tasks}}

【收获与成长】


【不足与反思】


【下周计划】
```

本功能在主 PRD 的本地周报能力上进行可选扩展。若本文档与既有核心业务规则冲突，应遵循以下优先级：

1. `today.txt` 与 `weeks/*.txt` 继续作为任务数据的唯一事实来源。
2. 默认生成方式继续完全本地，安装、启动、预览模板和编辑设置均不得自动联网。
3. 只有用户主动启用远程 LLM 并触发测试或生成时，应用才可以访问用户确认的服务地址。
4. 周报仍只写入用户通过系统保存对话框选择的位置，不在应用数据目录创建报告副本。
5. Renderer 不直接访问文件系统或远程服务，相关能力均通过受控 Preload API 进入 Main Process。

## 2. 背景与问题

当前应用只提供固定格式的 `TemplateAgent`：它可以稳定地把周任务拼接为纯文本，但不能满足以下需求：

- 不同用户和团队有不同的周报标题、章节、措辞与排版规范。
- 用户无法在保存前预览自定义模板应用后的实际结构。
- 固定模板只能罗列工作事项，不能自动概括成果、风险和后续计划。
- 国产大模型服务商的 API 地址、模型名称和密钥各不相同，用户缺少统一配置入口。
- 部分用户使用自建代理、本地模型或第三方兼容服务，需要自行填写 URL、API Key 和模型 ID。

同时，远程 LLM 会把本地任务正文发送到外部服务，与现有“默认无网络请求”的产品边界不同。因此，本功能必须把用户授权、发送范围、密钥保存和错误语义作为核心需求，而不能只实现一次 HTTP 请求。

## 3. 产品目标

### 3.1 核心目标

1. 用户能够分别编辑并持久化本地 TXT 工作记录模板和远程完整周报模板。
2. 用户能够在不联网的情况下分别预览两份模板。
3. 用户能够继续选择完全本地的模板生成方式。
4. 用户能够通过 DeepSeek、阿里云百炼/通义千问、月之暗面 Kimi、智谱 GLM 等国产服务商预设快速配置远程 LLM。
5. 用户能够配置符合 OpenAI Chat Completions 协议的自定义服务地址、API Key 和模型 ID。
6. 用户主动生成时，应用只把周信息、已完成工作记录、当前未完成待办候选、远程完整模板和写作提示词发送给已确认的服务地址。
7. 远程生成结果在保存前可预览和编辑。
8. API Key、任务正文、模板和模型结果不会进入诊断日志或遥测。

### 3.2 体验目标

- 不要求用户理解 SDK、请求 JSON 或 HTTP Header。
- 选择服务商预设后，只需填写 API Key 和模型 ID 即可测试连接。
- 自定义服务配置保持足够灵活，但不演变成通用 HTTP 调试器。
- 生成过程明确显示正在连接的服务商和模型，并允许取消等待。
- 失败时说明是认证、限流、网络、超时、模型配置还是响应格式问题。
- 不因远程失败破坏本地任务、模板或既有导出能力。

### 3.3 非目标

第一版不包含：

- 多套模板收藏、模板市场或在线模板同步。
- 任意 HTTP 方法、任意请求体脚本或用户 JavaScript。
- 自定义任意 HTTP Header、Cookie、代理脚本或 OAuth 登录。
- Anthropic Messages、厂商私有协议或工作流/智能体应用协议。
- 自动联网获取服务商模型列表。
- 流式输出和模型思考过程展示。
- 自动重试远程生成。
- 自动定时生成或上传周报。
- 向模型发送附件、日志、其他周数据或未识别 TXT 行。
- 在应用数据目录保存生成结果副本或历史版本。
- 云同步 API 配置、模板或生成结果。

## 4. 术语与产品模型

### 4.1 双周报模板

本地 TXT 工作记录模板是一段用户可编辑的纯文本，用于确定性地组织完成事项。远程完整周报模板定义最终周报结构。两者都保存在本机，不是业务任务数据源，且都使用同一组模板变量。

第一版支持以下模板变量：

| 变量             | 含义                 | 示例               |
| ---------------- | -------------------- | ------------------ |
| `{{iso_year}}`   | ISO week-year        | `2026`             |
| `{{iso_week}}`   | 两位 ISO 周编号      | `33`               |
| `{{week_start}}` | 该周周一日期         | `2026-08-10`       |
| `{{week_end}}`   | 该周周日日期         | `2026-08-16`       |
| `{{tasks}}`      | 按日期排列的完成事项 | 多行纯文本任务列表 |

`{{tasks}}` 为必需变量。模板至少出现一次 `{{tasks}}` 才能保存，防止生成结果意外遗漏全部完成事项。其他未知 `{{...}}` 变量视为校验错误。

### 4.2 本地模板生成

本地模板生成不调用 LLM。应用将模板变量替换为所选周的真实内容，生成确定性的纯文本结果。

### 4.3 远程 LLM 生成

远程 LLM 先取得由本地记录模板渲染出的事实工作记录，再结合远程完整模板、用户提示词和当前未完成待办候选组织最终结果。模型不得读取其他本地文件或调用应用内部能力。

### 4.4 远程写作提示词

提示词是用户可编辑的纯文本要求。应用仍保留不可被用户覆盖的系统级事实约束；用户提示词不能授权模型读取额外文件、绕过发送范围或改变网络安全策略。

### 4.4 服务商预设

服务商预设只是易用性配置，用于填入推荐 Base URL、服务商名称和帮助信息。DeepSeek、千问、Kimi、智谱等预设与“自定义服务”共用同一个 OpenAI 兼容协议实现，不形成各自独立的生成流程。

## 5. 用户场景

### 5.1 自定义团队周报格式

用户把团队要求的标题和章节粘贴到模板编辑器，使用当前周数据预览效果。保存后，下次启动继续使用该模板。

### 5.2 使用 DeepSeek 生成周报

用户选择 DeepSeek，填写 API Key 和模型 ID，测试连接成功后启用远程 LLM。点击“生成周报”时，应用提示本次将发送的内容范围，用户确认后获得可编辑的周报草稿。

### 5.3 使用其他国产模型

用户选择千问、Kimi 或智谱预设，预设自动填写对应的 OpenAI 兼容 Base URL。用户仍可修改模型 ID，以适应服务商模型更新或账户权限差异。

### 5.4 使用自建或代理服务

用户选择“自定义 OpenAI 兼容服务”，填写 Base URL、Bearer API Key 和模型 ID。默认要求 HTTPS；本机 Ollama 等服务可配置 `localhost` HTTP 地址。公网或局域网明文 HTTP 必须通过独立的高级风险确认后才允许连接。

### 5.5 远程服务不可用

远程请求超时或服务返回错误时，应用保留当前模板和任务，显示明确错误，并提供“重试”“改用本地模板”和“返回设置”操作，不静默伪装为远程生成成功。

## 6. 信息架构

设置窗口新增“周报生成”区域，建议分为三部分：

1. **本地 TXT 工作记录模板**
   - 模板编辑器与本地预览
   - 恢复默认模板
2. **远程完整周报模板与提示词**（仅在远程模式展示）
   - 完整模板编辑器
   - 从 `.txt` / `.md` 导入
   - 完整模板本地预览
   - 提示词编辑器
   - 分别恢复默认值
3. **生成方式**
   - 本地模板
   - 远程 LLM
4. **AI 服务**
   - 服务商预设
   - Base URL
   - API Key
   - 模型 ID
   - 高级参数
   - 测试连接
   - 隐私说明和授权状态

周记窗口的主操作由“一键导出周报 TXT”调整为“生成周报”。生成成功后进入结果预览，再由用户选择保存位置。

悬浮窗菜单和托盘菜单中的“导出本周周报”继续存在，但触发后应打开周记窗口并进入当前周生成流程，使所有入口共享相同的授权、进度、预览和保存体验。

## 7. 功能需求

### 7.1 模板编辑与持久化

#### RPT-TPL-01 模板编辑器

- 使用支持多行输入的纯文本编辑器。
- 支持粘贴、撤销、重做、全选和键盘操作。
- 第一版模板最大长度为 20,000 个 Unicode 字符。
- 模板为空、超过长度、缺少 `{{tasks}}` 或包含未知变量时不能保存。
- 模板文本不得被解释为 HTML，预览和结果均按纯文本安全展示。

#### RPT-TPL-02 保存语义

- 模板使用明确的“保存模板”操作，不随每次键入自动写盘。
- 保存成功后才更新当前生效模板。
- 保存失败时编辑内容保留在页面中，当前生效模板继续使用最后一次成功保存的版本。
- 模板保存后，在应用完全退出并重新启动后继续生效。

#### RPT-TPL-03 默认模板与恢复

- 首次使用时显示现有产品默认周报结构。
- “恢复默认模板”先更新编辑区并显示预览，用户确认保存后才替换当前模板。
- 恢复默认不得删除任务文件、API 配置或密钥。

#### RPT-TPL-04 模板变量

- 页面必须列出每个支持变量的名称、含义和示例。
- 点击变量可插入到当前光标位置，或提供明确复制操作。
- 同一变量可出现多次。
- 变量名称区分大小写，不允许缩写或模糊匹配。

### 7.2 模板预览

#### RPT-PREVIEW-01 本地预览

- 模板预览完全在本地运行，不发起网络请求。
- 优先使用周记窗口当前选中周的数据；若从设置直接打开且无法确定选中周，则使用当前周数据。
- 当前周没有完成事项时，用户可以在“空周预览”和“示例数据预览”之间切换，默认使用示例数据。
- 预览随编辑内容短延迟更新，但不写入磁盘。

#### RPT-PREVIEW-02 预览标识

- 预览区域明确标注“本地模板预览，不会调用 AI”。
- 使用示例数据时显示“示例数据”标识，不能让用户误认为这些事项来自自己的记录。
- 模板存在错误时，保留最后一次可渲染预览，并在编辑器附近显示具体错误位置或变量名称。

### 7.3 生成方式

#### RPT-MODE-01 默认模式

- 默认生成方式为“本地模板”。
- 从旧版本升级后继续使用本地模板，不因检测到 API 配置或模板文件而自动启用远程 LLM。
- 本地模式不要求 API Key，不显示远程连接错误。

#### RPT-MODE-02 启用远程模式

- 用户必须主动选择“远程 LLM”。
- 启用前必须完成合法服务配置并保存 API Key；测试连接建议但不作为强制前置条件。
- 切回本地模式时保留远程配置和加密密钥，方便以后重新启用；用户可单独清除密钥。

### 7.4 服务商预设与自定义服务

#### RPT-PROVIDER-01 预设范围

第一版提供以下选项：

| 选项                   | 说明                                    |
| ---------------------- | --------------------------------------- |
| DeepSeek               | 填入 DeepSeek 官方 OpenAI 兼容 Base URL |
| 阿里云百炼 / 通义千问  | 填入百炼中国区域 OpenAI 兼容 Base URL   |
| 月之暗面 Kimi          | 填入 Kimi 官方 OpenAI 兼容 Base URL     |
| 智谱 GLM               | 填入智谱官方 OpenAI 兼容 Base URL       |
| 本地 OpenAI 兼容服务   | 默认提示 `localhost`，API Key 可为空    |
| 自定义 OpenAI 兼容服务 | 用户填写 Base URL、API Key 和模型 ID    |

- 预设地址必须在每次发布前根据服务商官方文档验证。
- 预设不得锁定单一模型名称；模型 ID 始终允许编辑。
- 用户修改预设 Base URL 后，该配置应标记为“自定义”，避免仍显示为官方地址。

#### RPT-PROVIDER-02 Base URL

- 字段名称统一为“Base URL”，帮助文本说明应用会调用其下的 `/chat/completions`。
- 最大长度为 2,048 个字符。
- 只接受合法的 `https:` URL；`http:` 仅按安全规则例外允许。
- 拒绝包含用户名、密码、查询密钥、片段标识或不支持协议的 URL。
- 保存前规范化尾部 `/`，但不得擅自修改主机名或路径。

#### RPT-PROVIDER-03 API Key

- 云端预设默认要求 API Key；本地服务允许留空。
- 输入框默认使用密码样式，不显示历史明文。
- 已保存密钥只显示“已配置”和末尾少量掩码，不向 Renderer 返回完整值。
- 已保存密钥必须绑定保存时的服务 origin；Base URL 切换到另一个 origin 后，旧密钥不得自动发送，用户需要重新填写或明确保存对应密钥。
- 用户可替换或清除密钥。
- 清除后远程模式立即不可用，但不删除模板和非敏感服务配置。

#### RPT-PROVIDER-04 模型 ID

- 模型 ID 必填，最大长度为 128 个字符。
- 用户可以手动输入服务商实际提供的模型 ID。
- 第一版不自动拉取模型列表，避免设置页在打开时自动联网。
- 服务商返回“模型不存在或无权限”时，提示用户核对模型 ID 和账户权限。

#### RPT-PROVIDER-05 高级参数

第一版支持：

- Temperature：`0`–`2`，默认 `0.3`。
- 最大输出 Token：`256`–`32,768`，默认 `2,048`。
- 请求超时：`10`–`180` 秒，默认 `60` 秒。

高级参数折叠展示。若服务商拒绝某参数，应用应提示配置不兼容，不自动改成其他值后重试。

### 7.5 测试连接

#### RPT-CONNECT-01 测试内容

- 只有用户点击“测试连接”时才发起请求。
- 请求只包含最小固定测试文本，不包含任务、模板、本机路径或历史报告。
- 测试使用当前编辑中的 Base URL、API Key 和模型 ID，但不代表这些值已保存。
- 重复点击期间只允许一个测试请求。

#### RPT-CONNECT-02 测试结果

- 成功时显示服务主机、模型 ID 和测试时间。
- 失败时区分 URL 被阻止、DNS/网络失败、TLS 失败、认证失败、模型不可用、限流、超时和响应格式异常。
- 不把底层堆栈、响应 Header、API Key 或完整响应正文展示给用户。
- 测试成功不自动启用远程模式，仍需用户保存配置。

### 7.6 隐私授权

#### RPT-CONSENT-01 首次授权

用户第一次对某个远程服务生成周报前，应用必须明确展示：

- 将要访问的服务主机。
- 使用的模型 ID。
- 将发送所选周的日期、完成时间、本地工作记录、远程完整模板、写作提示词，以及当前未完成待办候选。
- 不发送其他周、未知 TXT 行、配置文件、日志或本机路径。
- 服务商可能根据自己的条款处理和保存请求。

用户必须主动确认后才能继续。

#### RPT-CONSENT-02 授权失效

以下任一项变化后，旧授权失效并需重新确认：

- Base URL 的 origin 变化。
- 从本地地址切换到远程地址。
- 服务商类型变化。
- 应用隐私声明版本变化。

只修改模型 ID、Temperature 或超时时间不要求重新授权，但生成页面应始终显示当前服务和模型。

### 7.7 生成与结果预览

#### RPT-GEN-01 输入数据

- 生成前读取目标周的最新 `WeeklySnapshot`。
- 当前周继续合并 `today.txt` 中尚未归档的已完成事项。
- 相同内容和完成时间的重复任务必须逐条保留。
- 只发送可识别的完成任务，不发送未知 TXT 行。
- 任务顺序遵循现有周记聚合规则。

#### RPT-GEN-02 本地生成

- 只使用当前生效的本地 TXT 工作记录模板替换变量并形成草稿。
- 不调用网络，不要求隐私授权。
- 空周使用明确的空状态文本，不注入示例数据到真实周报。

#### RPT-GEN-03 远程生成

- Main Process 将固定系统约束、用户提示词、本地模板渲染结果、远程完整模板、周上下文和当前未完成待办候选发送给配置的服务。
- 未完成待办只作为“下周计划”候选；模型不得把候选项描述为已经确定的承诺。
- 第一版使用 OpenAI Chat Completions 兼容协议，`stream` 固定为 `false`。
- 不启用工具调用、联网搜索、附件、函数调用或多轮对话。
- 模型返回的思考过程不展示、不保存，只读取最终文本内容。
- 响应为空、超出应用上限或仍包含未解析模板变量时，显示错误或明确警告，不直接保存。

#### RPT-GEN-04 进度与取消

- 生成期间显示服务商、模型和已等待时间。
- 用户可以取消本次等待。
- 取消后忽略迟到响应，不创建文件。
- 因网络超时或取消时，应用应提示请求可能已到达服务商并产生计费，避免承诺绝对未调用。

#### RPT-GEN-05 结果预览

- 无论本地或远程生成，都先进入结果预览。
- 用户可在预览中编辑纯文本结果。
- 编辑只存在于当前内存草稿，不反向修改模板或任务文件。
- 用户关闭或丢弃草稿时不创建任何报告文件。
- 第一版不提供草稿历史和自动恢复。

#### RPT-GEN-06 保存

- 用户确认草稿后，Main Process 打开系统保存对话框。
- 默认文件名继续为 `周报-YYYY年第WW周.txt`。
- 只写用户选择的位置，不在 `data/` 中保存副本。
- 保存成功后继续提供“打开文件”和“打开所在文件夹”。
- 取消保存不影响草稿，用户可以继续编辑或主动丢弃。

### 7.8 失败与降级

#### RPT-FAIL-01 禁止静默降级

- 远程生成失败时不得自动输出本地模板并标记为 AI 结果。
- 用户可以明确选择“改用本地模板”。
- 本地降级生成的结果必须标记为“本地模板生成”。

#### RPT-FAIL-02 重试

- 第一版不自动重试，避免重复请求和不可控计费。
- 用户点击重试时重新读取最新周数据并再次确认当前服务配置。
- 认证失败、模型无权限或 URL 被阻止时，应优先引导用户返回设置，不突出重试。

## 8. 安全与网络规则

### 8.1 网络默认值

- 新安装和旧版本升级后的默认模式均为本地模板。
- 打开应用、设置页、周记页或模板预览不产生远程 LLM 请求。
- Renderer 的现有生产网络封锁继续保留。
- 远程请求仅由 Main Process 的专用 LLM 客户端发出。

### 8.2 自定义 URL 安全

- 公网和局域网地址默认必须使用 HTTPS。
- `http://localhost`、`http://127.0.0.1` 和 `http://[::1]` 可用于本地服务。
- 其他公网或局域网 HTTP 地址默认拒绝；用户明确勾选“允许不安全 HTTP”并确认 API Key、模板和周报正文会被明文传输后才可使用。
- 不安全 HTTP 授权必须随连接配置持久化并持续显示警告，不与普通远程生成隐私授权合并。
- 禁止 `file:`、`data:`、`javascript:`、`ftp:`、`ws:`、`wss:` 等协议。
- 默认不跟随跨 origin 重定向。
- 连接过程中不得把 API Key 转发到另一个 origin。

### 8.3 密钥安全

- API Key 不写入普通 `config.json`、模板文件或日志。
- 密钥由 Main Process 使用操作系统支持的安全存储能力加密后保存。
- 若当前系统无法提供安全加密，应用不得静默明文保存；可以允许仅本次会话使用或要求用户取消。
- Renderer 只获得 `hasApiKey` 和安全掩码。
- 复制数据目录、打开日志和错误报告均不得暴露密钥。
- 加密密钥文件不保证跨设备可用，复制数据目录到另一台机器后需要重新填写 API Key。

### 8.4 内容和日志

- 日志不得记录任务正文、模板、生成结果、请求体、响应体、Authorization Header 或 API Key。
- 日志只记录服务商标识、经过校验的 origin、模型 ID、耗时、HTTP 状态类别和内部错误码。
- 对 URL 日志必须移除查询参数、用户名、密码和片段。
- 应用不实现遥测，也不把生成成功率发送给项目维护者。

## 9. 本地数据需求

### 9.1 目录结构

```text
data/
├── today.txt
├── weeks/
├── config.json
├── report-template.txt
├── remote-report-template.txt
├── report-prompt.txt
├── secrets.json
└── logs/
    └── app.log
```

- `report-template.txt` 保存本地 TXT 工作记录模板，UTF-8 无 BOM。
- `remote-report-template.txt` 保存远程完整周报模板，UTF-8 无 BOM。
- `report-prompt.txt` 保存用户可编辑的远程写作提示词，UTF-8 无 BOM。
- `secrets.json` 只保存加密后的密钥载荷、绑定的服务 origin 和必要版本信息，不保存任务、模板或生成结果。
- 未自定义模板或未保存密钥时，对应文件可不存在。
- 不创建 `reports/` 目录。

### 9.2 非敏感配置

`config.json` 可保存：

- 当前生成方式。
- 服务商预设 ID。
- Base URL。
- 模型 ID。
- Temperature、最大输出 Token 和超时时间。
- 模板相对路径。
- 隐私授权对应的服务 origin 与声明版本。
- 是否已配置密钥的事实不得依赖 config 中的布尔值，应以安全凭据服务为准。

### 9.3 兼容规则

- 旧配置缺少周报设置时自动使用默认本地模式。
- 现有 `agent: "template"` 与 `template_path: null` 继续可读取。
- 配置升级不得修改 `today.txt` 或周文件。
- 配置字段非法时只回退该字段，其他合法字段和未知字段继续保留。

## 10. 页面状态与反馈

### 10.1 设置页状态

- `loading`：读取当前模板、配置和密钥状态。
- `editing`：存在未保存模板或服务配置。
- `testing`：连接测试进行中。
- `saving`：模板、配置或密钥正在提交。
- `saved`：最后一次提交成功。
- `error`：显示局部错误并允许重试。

关闭设置窗口时若存在未保存修改，应提示“放弃修改”或“继续编辑”，不得静默保存 API Key 或远程模式。

### 10.2 生成状态

- `idle`：未生成。
- `preparing`：读取和规范化周数据。
- `awaiting-consent`：等待隐私确认。
- `generating`：等待本地或远程结果。
- `cancelling`：已请求取消，等待清理。
- `previewing`：查看和编辑草稿。
- `saving`：写入用户选择路径。
- `saved`：保存成功。
- `failed`：显示可恢复错误。

### 10.3 推荐错误文案方向

| 场景         | 用户反馈方向                                      |
| ------------ | ------------------------------------------------- |
| API Key 错误 | “认证失败，请检查 API Key 是否有效”               |
| 模型不可用   | “模型不存在、无权限或与当前服务地址不匹配”        |
| 请求过多     | “服务当前限流，请稍后手动重试”                    |
| 超时         | “等待模型响应超时，本次请求可能已到达服务商”      |
| URL 被阻止   | “该服务地址不符合安全规则，请检查协议和地址”      |
| 响应格式异常 | “服务返回了无法识别的结果，请确认其兼容 Chat API” |
| 本地模板错误 | “模板包含未知变量或缺少 `{{tasks}}`”              |
| 保存失败     | “周报未能写入所选位置，请检查目录权限后重试”      |

## 11. 非功能性需求

- **默认隐私**：未启用远程模式时保持默认零远程请求。
- **响应性**：模板预览在常规模板和周数据下应于 100 ms 内完成；输入防抖不超过 300 ms。
- **超时**：远程请求必须由可取消的超时控制，不允许无限等待。
- **可靠性**：模板和非敏感配置采用安全写入；失败不覆盖最后一次成功版本。
- **成本控制**：第一版不自动重试、不后台生成、不自动测试连接。
- **可访问性**：编辑器、模式切换、测试、生成、取消和保存均可通过键盘完成并具有清晰标签。
- **兼容性**：支持目标平台 macOS 11+ 与 Windows 10+；密钥保存行为需在两平台实机验证。
- **可维护性**：服务商预设与协议实现分离，新增预设不复制 HTTP 调用逻辑。
- **可测试性**：自动化测试使用本地假服务，不在 CI 调用真实模型或依赖真实 API Key。

## 12. 验收标准

1. 旧版本用户升级后仍默认使用本地模板，启动、打开设置和模板预览均不调用远程服务。
2. 用户可分别编辑并保存本地记录模板、远程完整模板和提示词，完全退出后重新启动仍保持。
3. 空模板、超过长度、未知变量或缺少 `{{tasks}}` 时不能保存，并显示明确原因。
4. 模板预览使用当前周或示例数据在本地完成，界面明确标识且不消耗 API。
5. 恢复默认模板不会删除任务、LLM 配置或 API Key。
6. 本地模式只按本地记录模板生成；远程模式使用本地记录、完整模板和提示词生成，重复任务全部保留。
7. 设置页提供 DeepSeek、千问、Kimi、智谱、本地服务和自定义服务选项。
8. 选择预设后自动填入经发布验证的 Base URL，模型 ID 仍可编辑。
9. 用户可以配置合法的 OpenAI 兼容 Base URL、Bearer API Key 和模型 ID。
10. 非法协议、内嵌凭据、非法 URL 和默认不允许的明文远程地址被拒绝。
11. 测试连接只发送固定测试内容，不包含任务、模板、路径或历史报告。
12. API Key 加密保存并绑定服务 origin；切换 origin 后旧密钥不会被发送，也不出现在 `config.json`、模板文件、日志、IPC 返回快照或错误信息中。
13. 系统无法安全加密时，不会静默明文保存 API Key。
14. 第一次向某个远程 origin 生成前显示准确的数据发送范围并要求主动确认。
15. 更改远程 origin 后旧授权失效，下一次生成重新确认。
16. 远程生成只发送所选周信息、可识别完成任务、本地记录、完整模板、提示词和当前未完成待办候选。
17. 其他周内容、未知 TXT 行、日志、配置和本机路径不会发送；当前未完成待办仅用于下周计划候选。
18. Main Process 发起远程请求，Renderer 保持生产网络封锁且无法读取密钥。
19. 远程结果生成后先显示可编辑预览，确认前不创建周报文件。
20. 用户取消生成、丢弃草稿或取消保存时，不在应用数据目录创建报告副本。
21. 保存成功时只写系统保存对话框选择的位置，并继续支持打开文件和定位目录。
22. 认证、限流、超时、连接、URL 策略和响应格式错误具有可区分反馈。
23. 远程失败不会静默回退；用户主动选择本地模板后结果有明确来源标识。
24. 取消或超时后的迟到响应不会覆盖当前草稿或自动触发保存。
25. 自动化测试不访问真实 LLM，不读取开发者真实密钥或业务数据目录。
26. macOS 和 Windows 实机验证密钥保存、连接测试、生成取消、结果预览和保存流程。

## 13. 测试建议

### 13.1 模板测试

- 所有变量替换正确。
- 两位周编号、跨 ISO 年和空周正确。
- 重复任务不去重。
- 未知变量、缺少 `{{tasks}}`、长度上限和特殊字符。
- 模板内容按纯文本展示，不执行 HTML 或脚本。

### 13.2 配置与密钥测试

- 旧配置迁移到默认本地模式。
- 服务商预设与自定义地址切换。
- origin 变化使授权失效。
- 密钥保存、替换、清除和加密不可用。
- 配置写入失败保持最后成功状态。

### 13.3 网络与 Agent 测试

- 本地假 OpenAI 兼容服务返回成功。
- 400、401、403、404、429、5xx、超时、断网和非法 JSON。
- 空内容、超长内容和缺失 `choices[0].message.content`。
- 重定向到不同 origin 被拒绝且密钥不转发。
- 取消请求后迟到响应被忽略。
- 日志内容不包含密钥、Authorization、任务、模板或模型完整响应。

### 13.4 Renderer 与手工测试

- 模板编辑、变量插入、预览、保存和恢复默认。
- 服务商切换、密钥掩码、测试连接和错误反馈。
- 隐私确认、生成进度、取消、结果编辑和保存。
- 菜单、托盘与周记窗口进入同一生成流程。
- macOS 和 Windows 上的安全存储、系统保存对话框和键盘操作。

## 15. 已确认的产品决策

1. 第一版统一使用 OpenAI Chat Completions 兼容协议。
2. DeepSeek、千问、Kimi、智谱作为配置预设，共用同一远程 Agent 实现。
3. 用户可以自定义 Base URL、Bearer API Key 和模型 ID。
4. 不开放任意 Header、请求脚本或通用 HTTP 调试能力。
5. 默认本地、远程按需、首次发送需明确授权。
6. 模板预览完全本地；远程结果另有保存前预览。
7. API Key 加密单独保存，不能进入普通配置和日志。
8. 远程失败不静默回退，由用户决定是否改用本地模板。
9. 生成结果仍只保存到用户选择的位置，不建立应用内报告历史。
