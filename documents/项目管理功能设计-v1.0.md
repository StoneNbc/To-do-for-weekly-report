# 项目管理功能设计

版本：v1.0。更新：2026-09-09。状态：首版已实现，验证证据与平台限制见 [PROJECT_STATE](PROJECT_STATE.md)。

配套文档：[项目管理开发文档](项目管理开发文档-v1.0.md)。当前实现与验证状态统一见 [PROJECT_STATE.md](PROJECT_STATE.md)。

## 1. 目标与已确认决定

用户可以先创建项目，再在项目中创建、整理和完成待办，并按项目回顾工作与生成周报。

本轮已确认的核心决定：

- 任务在 TXT 中直接保存项目名，不引入项目编号，也不引入持久化任务 ID。
- 项目改名时，统一更新项目目录、当前任务和历史周文件中的项目字段。
- 替换只针对解析后的项目字段，正文、详情、注释和未知行中的同名文字不改。
- 项目名称已经存在时拒绝普通重命名；项目合并不纳入第一版。
- `projects.txt` 保存空项目、状态和顺序；周报生成不需要将该文件发给 LLM，也不需要用它解释任务归属。
- 本轮只完成设计与开发文档，不实现、提交、推送或发布功能。

以下交互与异常规则是本版的实施默认方案；后续如调整，先同步本文及配套开发文档。

## 2. 功能范围

| 第一版包含                                             | 暂不包含                       |
| ------------------------------------------------------ | ------------------------------ |
| 创建、重命名、排序、归档、恢复项目，删除无引用的空项目 | 子项目、成员、权限、云同步     |
| 全部项目、未分类、单项目视图                           | 每个项目独立悬浮窗             |
| 在项目下添加待办、单条移动待办、项目行快捷添加         | 拖拽排序任务、看板、任务依赖   |
| 历史记录及完成归档保留项目名                           | 历史状态快照、项目名称变更历史 |
| 周记项目筛选、本地及远程周报按项目整理                 | 自动合并同名项目、完成率仪表盘 |

项目颜色为可选信息，默认使用现有主题中的中性标识；不自动修改便利贴背景色。没有项目的旧任务不影响现有使用流程。

## 3. 项目与待办模型

一个待办最多属于一个项目，项目归属为空时属于“未分类”。“全部项目”和“未分类”是系统视图，不是用户项目，名称保留。

项目以名称唯一识别。名称去除首尾空白，长度为 1–80 个 Unicode 码点；不允许换行、控制字符。内部空格、中文和常见标点允许使用。按保存后的名称精确比较，区分大小写，不自动转换全角／半角或合并相似名称；已归档项目也参与重名检查。

项目包含名称、`active`／`archived` 状态、可选颜色；项目块在目录中的顺序就是用户排序。待办保留标题、详情、完成状态、添加日期和完成时间，增加可空的项目名。

任务仍以文件上下文中的 `revision + line` 定位。允许同一项目内或跨项目存在完全重复的待办，不按标题定位或去重。

## 4. 便利贴界面与操作

视觉基准（2026-09-10）：用户选定 Product Design 方案 2。项目采用轻描边和柔和阴影的独立分组，数量紧随名称，右侧“＋”使用浅蓝圆形按钮；上方新建按钮与底部添加按钮为蓝色主操作。底部输入区在容器宽度至少 380px 时横向排列，窄窗口分行。默认背景为珍珠灰，已有自定义颜色不自动覆盖。紧凑态标题栏尺寸和控件占位保持原约束。该说明是选定视觉的实现规则，不代表视觉验收已完成。

### 4.1 项目选择

沿用一个悬浮窗，在原标题栏下新增一行项目选择器。固定窗口尺寸不变，新增一行会减少任务列表可见高度；紧凑模式隐藏项目栏，保留原标题栏控件占位、菜单恢复和展开行为。

```text
‹ 9月9日 · 今天 ›                    收起 ⋯
云网吧交付 ▾                     3 项待完成
─────────────────────────────────────────
□ 确认服务器配置
□ 整理网络拓扑
  › 查看详情
□ 与客户确认验收指标

› 当日已完成 2

＋ 添加到「云网吧交付」…
```

选择器提供“全部项目”“未分类”和进行中的项目；旁边的“新建项目”打开独立创建窗口，“项目管理”打开管理面板，面板支持按名称搜索并可打开同一创建窗口。计数表示当前未完成任务数，不随历史日期改变；历史列表另按日期规则筛选。

首次升级默认“全部项目”，以后记住上次选择。切换项目保留日期，切换日期保留项目。长名称省略显示并提供完整文本提示。编辑未保存时，切换项目或日期应先保存／取消，不能丢弃编辑内容。

“全部项目”按项目分组，未分类在末尾；组内保持原任务顺序，分组折叠只改变视图，不重排 TXT。当天完成记录仍集中在“当日已完成”区域，展开后按项目分组。

### 4.2 创建与添加

新建项目在独立应用窗口中填写名称与可选颜色；重复点击复用同一个窗口。成功后关闭创建窗、自动选择新项目并聚焦添加框；失败保留输入，取消不创建项目。创建窗打开期间禁止主便利贴自动贴边隐藏。

“全部项目”的待办区保留所有已登记、进行中的项目，包括零待办项目并显示计数 0；空的已归档项目不展示。已完成区仍只显示有记录的分组。单项目无待办时保留空态与输入入口。

待办项目行右侧提供“＋”按钮，点击后选中该项目、保持当前日期及已有输入，并把光标移到下方添加框；未分类同样支持。按钮与分组折叠按钮分离，编辑／保存期间禁用，已归档或未登记项目不提供新增入口。

| 视图     | 新待办默认归属                                                         |
| -------- | ---------------------------------------------------------------------- |
| 单项目   | 当前项目                                                               |
| 未分类   | 无项目字段                                                             |
| 全部项目 | 输入框旁明确显示归属选择，初始为未分类；本次选择可在当前页面会话内保留 |

历史模式新增仍使用当前的历史补录规则，并继承所选项目。项目归属选择不能改变添加日期语义。

### 4.3 移动待办

任务旁的 `⋯` 打开编辑器，通过“所属项目”选择进行中的项目或未分类。移动保留标题、详情、日期和状态，只改归属。任务离开当前筛选范围后显示目标项目提示，不弹出额外确认。

主页不再提供“整理”与批量选择入口。单条当前或历史任务可在编辑器中更正项目归属；底层已有批量移动 API 保留兼容，其 revision／原始行号校验不变，不作为当前用户流程。

## 5. 项目生命周期

| 操作         | 行为                                                           |
| ------------ | -------------------------------------------------------------- |
| 重命名       | 修改目录与当前／历史任务项目字段，历史视图统一显示新名称       |
| 排序／改颜色 | 只修改目录信息                                                 |
| 归档         | 仅无未完成任务时允许；从日常选择器隐藏，管理页可查看           |
| 恢复         | 恢复为进行中并重新加入日常选择器                               |
| 删除         | 仅允许没有任何当前任务或历史完成记录引用的项目，删除前明确确认 |

项目归档不删除任务、不改完成日期，与每日任务写入周文件的“完成归档”是两件事。历史及周报项目选择器包含所选期间有记录的已归档项目；“全部”统计也包含它们。

重新打开已归档项目的完成任务时，先引导恢复项目，再重新打开任务；恢复项目成功、任务恢复失败时如实提示，任务仍保持完成状态。归档或删除当前项目后，日常视图切换为“全部项目”。

手工编辑造成已归档项目出现未完成任务时，不能将它们隐藏；“全部项目”显示该分组并标注“已归档，存在待办”，提供恢复入口。

## 6. TXT 数据格式

### 6.1 当前任务

以下是未来新格式的完整示例。`!format:projects-v1` 是任务文件格式声明，与应用版本、项目目录版本分开；当前应用尚不支持此格式。

```text
# 2026-09-09
!format:projects-v1

- [ ] 确认服务器配置 @项目:云网吧交付 @添加:2026-09-09
  | 核对 CPU、内存和显卡型号
- [ ] 设计项目切换功能 @项目:便利贴开发 @添加:2026-09-09
- [ ] 发送确认函 @项目:"客户 A 交付" @添加:2026-09-09
- [x] 完成需求讨论 @项目:便利贴开发 @添加:2026-09-09 @15:30
- [ ] 买打印纸 @添加:2026-09-09
```

项目字段位于添加日期前，完成时间仍在行尾。日期字段可省略；没有项目字段表示未分类。名称没有空白、引号或反斜杠时直接书写；其他名称用 JSON 双引号字符串，例如 `@项目:"客户 A 交付"`。界面负责自动编码，用户不需要手动转义。

连续 `  |` 详情行归属上方任务，不重复写项目名。项目字段不是正文，也不能放在详情里让解析器猜测。

### 6.2 项目目录

```text
# projects:v1

## 云网吧交付
状态: active
颜色: #22C55E

## 客户 A 交付
状态: active

## 旧网站改版
状态: archived
```

目录标题 `## ` 后直到行尾都是项目名称，内部空格直接保留，不使用任务字段的引号语法。目录按块排列，状态必填，颜色可省略；空目录只有首行版本声明。未知行保留，不自动当作项目或任务。

### 6.3 历史周文件

保留现有周头、日期头与无复选框的完成任务格式，加入同一个格式声明和项目字段。例如 `weeks/week-2026-W37.txt`：

```text
# 第37周 (2026-09-07 ~ 2026-09-13)
!format:projects-v1

## 周三 09-09
- 完成需求讨论 @项目:便利贴开发 @添加:2026-09-09 @15:30
  | 已确认项目名直接保存到 TXT
```

详细语法、正文转义和旧文件升级规则见开发文档 §3、§8。格式声明用于区分旧正文和新字段，不是项目 ID。归档仍使用 ISO week-year 命名。

## 7. 重命名与手工编辑

例如“云网吧交付”改为“云网吧一期交付”，应用在一次操作中更新：项目目录中的名称、`today.txt` 中匹配的项目字段、所有有效历史周文件中匹配的项目字段。

以下内容不在改名范围：任务标题及详情、注释／未知行、已导出的周报、用户模板与提示词、其他数据目录、备份和日志。当前界面筛选及缓存随成功结果刷新；已经生成的草稿是旧素材快照，提示重新生成，不静默改写。

改名前展示受影响任务数和文件数，用户提交后先完成备份，再执行替换。新名与旧名相同视为无操作；与其他项目或未登记但被任务引用的名称相同则拒绝，不能隐式合并。

多文件改名不宣称具有严格事务性。部分失败时显示恢复状态；应用尽可能安全回滚。无法自动恢复时保留备份与恢复入口，暂时暂停任务／项目写入和周报生成，避免继续扩大不一致。

手工修改 `projects.txt` 的名称不会自动推断为重命名，因为它也可能是删除旧项目并创建新项目。未同步修改的任务仍属于原名称，并显示“未登记项目”；可登记该名称或使用应用统一重命名。删除目录文件不会使任务失去项目名。

## 8. 日期、历史和周记

项目与日期是独立筛选维度。未完成任务跨日保留；正常完成使用 Main 时钟，历史补录使用所选日期。完成、撤销、跨日归档、历史完成、重新打开均携带项目名和整个详情块。

历史页沿用现状：上方显示添加日期不晚于所选日期的当前未完成任务，旧任务没有添加日期时保留；下方显示所选日期完成记录。它不是所选日期当时的全量任务状态快照。

周记可选择全部、未分类、一个或多个项目，并按日期或项目展示。当前周继续合并周文件和当天尚未归档的完成项，不按正文去重。计数按筛选后的任务条数计算，空项目不贡献完成条数。

## 9. 周报与远程 LLM

在本地从任务字段读取项目名，筛选并整理为素材，再发起一次正常生成请求；不上传 `projects.txt`，不增加项目查询请求。

```text
项目：云网吧交付
- 2026-09-09：确认服务器配置

项目：便利贴开发
- 2026-09-09：完成项目管理功能设计
```

生成页明确显示周范围、项目范围及是否纳入当前未完成待办作为下周计划候选；后者第一版默认关闭，启用后仅纳入所选项目的候选。菜单入口也先进入同一生成流程，不能绕过范围选择。

本地默认继续按日期输出，用户可选择按项目整理；原自定义模板不自动覆盖。任务内容仍只投影标题；项目名作为独立分组信息，日期和原有可选完成时间保留。详情不进入周记任务内容、周报或远程请求。

远程发送预览必须包含实际将发送的项目名、所选周完成记录、可选待办候选、模板和写作提示词。目录状态、颜色、排序、空项目、其他周记录、原始 TXT、未知行、路径和备份不发送。现有网络限制、Main 校验、凭据管理与用户主动授权继续有效；增加项目名须更新隐私文案版本，不把本次设计确认当作未来实际联网授权。

周报仍只写用户选择的位置，不创建内部周报副本、导出记录或提醒。

## 10. 异常与兼容体验

- 旧文件无项目字段：正常显示为未分类，不在读取时批量重写。
- 未登记项目：按任务中的原名称显示，不丢失、不归并到未分类；提供登记或移出入口。报告可直接使用该名称。
- 重名目录块、非法状态或项目字段：显示格式问题，保留原文；影响写入定位或全量扫描时阻止相关操作，不能假装处理成功。
- 外部编辑导致 revision 变化：返回 `FILE_CHANGED`，保留尚未提交的输入，刷新后重新选择任务。
- 旧应用无法理解新项目字段和格式声明，不能承诺可安全降级写入。首次升级受影响文件前保存备份；回退需恢复对应备份，新版新增数据应先另行保留。

## 12. 实施交接

实现顺序、接口、恢复机制和测试清单见[开发文档](项目管理开发文档-v1.0.md)。本文件是项目管理增量行为的依据；原 PRD、详情设计、周报设计中未被本功能明确调整的规则继续适用。界面默认方案可在原型验收时细化，但不得退回项目编号或直接对全文进行名称替换。
